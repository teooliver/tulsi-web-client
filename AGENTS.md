## Stack

- **Foldkit** + **Effect 4.1** (SPA mode), built with **Vite** and
  `@foldkit/vite-plugin` (required: it stamps route view identity).
- **oxlint** (with the Foldkit plugin and a type-aware Effect config) and
  **oxfmt** for formatting.
- **vitest** with Foldkit's `story` and `scene` test styles.
- **CSS Modules** + design tokens. **No Tailwind**, no CSS-in-JS.
- **pnpm** (pinned in `packageManager`), Node 24 (`.nvmrc`).

## Commands

```bash
pnpm dev               # regenerate CSS Module types, start Vite
pnpm build             # production build to dist/
pnpm test              # vitest run (test:watch for watch mode)
pnpm lint              # oxlint + Effect type-aware lint
pnpm format            # oxfmt --write (format:check to verify)
pnpm typecheck         # tsc --noEmit
pnpm css-types         # regenerate *.module.css.d.ts (css-types:watch)
pnpm api:spec          # download api/openapi.json (backend must run on :8080)
pnpm api:generate      # regenerate src/api/generated.ts from api/openapi.json
pnpm check             # format:check, css-types:check, api:check, lint,
                       # typecheck, test
```

Run `pnpm check` before finishing a change.

## API

See `docs/adr/0001-api-client-generation.md` for why it works this way.

- `api/openapi.json` is a committed copy of the backend spec. When the backend
  changes, run `pnpm api:spec` then `pnpm api:generate` and commit both.
- **Never hand-edit `src/api/generated.ts`.** It is generated by
  `@effect/openapi-generator` via `scripts/api.mjs`, skipped by lint and format,
  and `pnpm check` fails if it is stale.
- `src/api/client.ts` owns everything else:
  - `Api`, the shared client provided once as a Foldkit Resource in
    `entry.ts` (base URL from `VITE_API_URL`, default `http://localhost:8080`).
    Use `api.anonymous` for sign in and register, `api.authorized(token)` for
    everything else.
  - `toApiError`, which maps every failure into the `ApiError` union
    (`Unauthorized | NotFound | Conflict | BadRequest | ServerError |
NetworkError | InvalidResponse`).
- API calls are Commands: yield `Api`, call the generated function, and
  `Effect.catch` through `toApiError` into a `Failed*({ error: ApiError })`
  Message. An update whose Commands use `Api` declares it as the Resources
  type argument (`Update.Return<Model, Message, Api>`).
- Page Models use the generated Schemas (e.g. `User`, `Task`) directly. Write
  our own domain Schema only where the API shape or names diverge from the
  glossary.
- Requests go straight to the backend (no dev proxy); the backend's CORS allows
  it in development.

## Session

- The Model is `SignedOut | SignedIn { session }`. The Session holds the access
  token as `Redacted` (`AccessToken` in `src/domain/session.ts`) so devtools and
  logs never show it. Passwords typed into forms are `Redacted` too.
- The Session is read from localStorage at startup (Flags in `src/main.ts`) and
  written or cleared only by the `SaveSession` / `ClearSession` Commands.
- A restored Session is checked with `/auth/me`. A 401 from any authorized
  request should reach the root as an OutMessage that signs the User out (see
  `ExpiredSession` in `src/page/signedIn`). A 401 from sign in is a form error.

## Styling

- Design tokens (colours, spacing, radii, fonts, type scale) are CSS custom
  properties in `src/styles/tokens.css`. Light/dark follows
  `prefers-color-scheme`. Use tokens, not raw values, in component CSS.
- `src/styles/global.css` holds the reset and base element styles only. It is
  linked from `index.html`.
- Each view gets a CSS Module next to it (`view.ts` and `view.module.css`) and
  applies classes with `h.Class(styles.name)`. Shared form pieces live in
  `src/ui/form.ts`.
- Every `*.module.css` has a generated, committed `*.module.css.d.ts` (from
  `typed-css-modules`) so a mistyped class name is a type error. After adding,
  renaming or removing a class, run `pnpm css-types`. `pnpm check` fails if they
  are stale. Never hand-edit them.

## Testing

Follow `FOLDKIT.md`: `story.test.ts` drives `update`, `scene.test.ts` drives the
rendered `view`, colocated with the code they test. Tests run in vitest with
`happy-dom`. The setup is `src/vitest-setup.ts`. Shared fixtures live in
`src/testing/`. API Commands are resolved as data in tests, so they need no
HTTP mocks; `src/api/client.test.ts` covers the client and error mapping with a
fake `HttpClient`.

## Conventions

- Use the domain vocabulary in `../../tulsi-home/GLOSSARY.md` (the Tulsi Home
  Repo, checked out beside this repo's parent folder; if you cloned this repo
  alone, read it at https://github.com/teooliver/tulsi-home/blob/main/GLOSSARY.md).
  Name things with its canonical terms in code, docs and responses, and avoid
  the synonyms it lists. Foldkit terms (Model, Message, Command, Submodel) are
  implementation vocabulary, not domain terms.
- Keep `src/entry.ts` as the only place that boots the runtime.
- Use `@foldkit/ui` headless components (e.g. `Button`) for accessible
  interaction patterns, styled with our CSS Modules.
